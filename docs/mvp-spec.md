# MVP 기능명세

현 MVP의 **범위 — 무엇을 하고 안 하는가**. 목표: 부가가치세 신고 실무자가 법령 질문에 근거를 추적할 수 있는 답을 받는다.

## 1. 하는 것

| 기능 | 설명 |
|---|---|
| 법령 Q&A 채팅 | 질문 → 법령 검색 → 근거 기반 답 (`POST /api/chat`) |
| 이어지는 대화 | 직전 3턴까지 반영, 후속 질문을 혼자 이해되게 다듬어 검색 |
| 인용 + 하이라이트 | 답의 인용을 클릭하면 원문 모달, 해당 구간 강조 |
| 사용자 피드백 | 👍/👎를 기록(`POST /api/feedback`) |
| 새 대화 시작 | 버튼으로 세션 초기화 |
| 대화 저장 | 대화·메시지를 한 번에 DB 기록 ([db-schema](./db-schema.md)) |
| 예시 질문 | 첫 화면에 카테고리별 예시 노출 |
| 남용 방지 | IP당 분/일 한도 + 전체 일 한도 |

## 2. 안 하는 것 (현 단계 제외)

- 로그인·계정·권한 (단일 익명 사용자)
- 과거 대화 목록 탐색 화면 (저장만 됨)
- 법령 자동 갱신 (수동 `pnpm ingest:*`)
- 답 실시간 타이핑 (한 번에 표시)
- 다국어·모바일 앱·결제

## 3. 전제

- **토이 규모** — 조각 수백~수천 개. 검색 인덱스 기본값으로 충분.
- **모델 1개씩** — 생성 OpenAI / 검색 Voyage. 교체는 어댑터 한 파일.
- **별도 서버 없음** — Next.js가 `packages/core`를 직접 호출.
- **설정 없으면 그 기능만 건너뜀** — 기록·남용방지 도구 미설정이어도 채팅은 동작.
- **근거 우선** — 모든 인용은 검색된 조문에 연결, 미검증 인용은 강조 생략 또는 제거.
- **품질은 사후 측정** — 실시간 분기 없이, 검색·답 품질은 평가로 따로 잰다 ([evaluation](./evaluation.md)).

## 4. 사용자 · 유스케이스

**액터**: 부가가치세 신고 실무자(개인사업자·세무 담당). 익명, 로그인 없음.

### UC-1. 법령 근거 답변 (메인)

- **목표**: 신고 요건·세액·기한을 법령 근거와 함께 확인.
- **전제**: 법령이 DB에 적재된 상태.
- **기본 흐름**:
  1. 질문 입력 ("간이과세자는 1년에 부가가치세를 몇 번 신고하는가?").
  2. 시스템이 관련 조문을 검색해 근거 기반 답 + 인용을 제시.
  3. 사용자가 인용을 클릭 → 원문 모달에서 해당 구간 강조 확인.
- **예외**:
  - 관련 조문 없음 → "공식 자료에서 확인되지 않습니다" 안내(없는 근거를 지어내지 않음).
  - 한도 초과 → 429 안내 후 잠시 후 재시도.

### UC-2. 이어지는 질문 (멀티턴)

- **목표**: 앞 답에 이어 후속 질문.
- **기본 흐름**:
  1. UC-1(간이과세 신고) 뒤 "그럼 세금계산서는 발급해야 해?" 입력.
  2. 시스템이 직전 3턴 맥락을 합쳐 "간이과세자도 세금계산서를 발급해야 하는 경우는?"처럼 혼자 이해되는 질문으로 다듬어 재검색·답변.
- **전제**: 같은 대화 세션. 새 대화 시작 시 맥락 초기화.

### UC-3. 답변 피드백

- **목표**: 답 품질 신호 남기기.
- **기본 흐름**: 답이 유용/부정확하면 👍/👎 → 기록(오프라인 분석용, 즉시 반영 아님).
